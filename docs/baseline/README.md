# 리팩토링 기준선 (baseline) — 2026-09-03

`docs/refactor-plan.md` §4-3 / §6-A가 요구하는 기준선이다.

## 이게 뭐고 왜 있나

리팩토링은 **화면이 1px도 안 바뀌어야** 통과다. "안 바뀐 것 같다"는 증거가 아니므로,
리팩토링 **시작 전에** 화면의 모든 요소가 실제로 받고 있는 CSS 값을 전부 기록해뒀다.
단계마다 같은 걸 다시 떠서 이 값과 비교한다.

🔴 **기준선은 PHASE 0 시작 전 딱 한 번만 뜬다. 단계마다 새로 뜨면 안 된다.**
매번 직전과만 비교하면 한 단계에 1px씩 밀리는 드리프트를 영원히 못 잡는다(20단계면 20px).

---

## 🔴 이 도구를 만들면서 밟은 함정 4개 — 하나라도 어기면 기준선이 거짓말을 한다

전부 실제로 겪었다. 처음 만든 계측은 **아무것도 안 고쳐도 "26개 달라졌다"**고 답했다.

### ① 애니메이션을 0프레임에 고정하지 않으면 5개가 매번 다르다
배경 `blob a/b/c`(drift 10s 무한) · `.sun-icon`(spin 20s 무한) ·
`circle`(curveEndpointPulse 2.6s 무한)이 매 프레임 `transform`이 다르다.
👉 `document.getAnimations()`를 전부 `pause()` + `currentTime = 0`.

### ② 순서번호(index)를 키로 쓰면 안 된다 — **DOM 경로**를 키로 써라
`<head>`에 Next.js 개발 서버가 넣는 `<script>` 개수가 매 로드마다 다르다.
앞에서 2개만 늘어도 뒤 요소 전부가 한 칸씩 밀려 "1,500개 전부 달라졌다"가 된다.
👉 `body` 안만 보고, 키를 `DIV[1]>MAIN>DIV...` 같은 경로로 만든다.
👉 그리고 **"값이 다른 것"(회귀 신호)과 "요소가 생기고 없어진 것"(내용 로딩 차이)을 따로 센다.**

### ③ 뷰포트를 바꾼 뒤 **반드시 재로드**해라
`main.page`의 높이는 `var(--app-vh)` — **JS가 실측해 넣는 값**이다(핸드오프 28-3).
창 크기만 바꾸고 재로드를 안 하면 그 값이 옛 뷰포트 것으로 남아 `body`·`.sp-body`·`main.page`와
Key Notes 포스트잇이 어긋난 채로 찍힌다.

### ④ 💀 **테마를 `data-theme` 속성으로 직접 바꾸지 마라 — 앱과 경합한다**
이게 "26개 달라졌다"의 진짜 원인이었다. 달라진 값을 열어보니 전부
**다크값 → 라이트값**이었다. 즉 내가 속성을 바꿔도 앱이 자기 상태로 되돌려놓고 있었다.

테마의 주인은 하나다: `localStorage.skillpilot_theme` + 쿠키 `skillpilot_theme`를
**`layout.tsx`의 인라인 스크립트가 첫 페인트 전에** `<html data-theme>`에 적용한다
(`Dashboard.tsx:1368~1400` 주석: "판별은 인라인 스크립트 한 곳뿐이다").

👉 **테마는 `localStorage` + 쿠키를 쓰고 재로드**한다. `__prepTheme(t)`가 그 일을 한다.
   속성을 손으로 붙이는 경로는 만들지 마라 — 두 번째 기전이 된다.


### ⑤ 💀 CSSTransition을 0프레임에 멈추면 **직전 값**이 기록된다
동결(`__frozen`)은 애니메이션을 `currentTime = 0`으로 보낸다. 무한 keyframe 애니메이션에는 맞지만
**진행 중인 트랜지션에는 "바뀌기 전 값"을 박아버린다.** 기준선을 뜰 때 테마 색 트랜지션 11개가
진행 중이었고, 그래서 dark 기준선의 그 11개 자리에 **light 값이 들어갔다.**

👉 판정에 쓸 때는 **양쪽을 같은 방법으로** 재면 문제가 없다(둘 다 같은 값이 박힌다).
   🔴 **다만 `a.finish()` 같은 걸로 조건을 바꾸면 그 순간 기준선과 어긋나 "33개 달라졌다"가 뜬다.**
   조건을 바꿨으면 기준선도 다시 떠라. 섞어 쓰지 마라.

### ⑥ 💀 Browser 패널이 숨겨져 있으면 **프레임이 없다**
- 페이지 안 `setTimeout`이 심하게 억제된다 → **로딩 대기 루프를 페이지 안에 두면 도구가 타임아웃한다.**
  대기는 도구 쪽(`computer` `wait`)으로 빼라.
- **트랜지션이 영원히 안 끝난다**(진행에 프레임이 필요하다). `getAnimations()`에 계속 남는다.
- 타임아웃 난 호출은 **페이지에서는 계속 돌고 있다.** 겹쳐서 여러 벌 돌면 동결/복원이 어긋나
  애니메이션이 `paused`로 남고 그 뒤 측정이 전부 오염된다 → **재로드로 지우고 다시 시작해라.**

### ⑦ 내용이 바뀌는 영역은 `값이다른것`에도 잡힌다 — 날씨가 그렇다
날씨는 실시간이다. 기준선 때 `26°C 맑음 · 습도 74% · 대기질 보통`이었는데 몇 분 뒤
`27.2°C 구름많음 · 습도 66% · 대기질 좋음`이 됐다. **글자가 바뀌면 폭이 바뀌고**(`width`가
측정 20속성에 들어 있다) 날씨 위젯 하위 5~7개가 "값이 다르다"로 뜬다. 회귀가 아니다.

## 🔴 그래서 판정은 이렇게 한다 — **대조군을 같이 재라**

`값이다른것`이 0이 아닐 때 "회귀다/아니다"를 기준선만으로는 못 가린다. 방법은 하나다:

1. 변경을 **되돌린** 상태로 재서 달라진 요소 집합을 얻는다 (= 대조군)
2. 변경을 **얹은** 상태로 재서 집합을 얻는다
3. **두 집합이 같으면 그 변경은 화면을 안 바꿨다.** 다르면 그 차집합이 곧 회귀다

PHASE 0 ②(헬퍼 1,282줄 이동)를 이 방법으로 판정했다 —
1280에서 7개 / 375에서 5개가 양쪽 모두 **완전히 같은 집합**(전부 날씨 위젯 하위)이었다.

## 뜬 방법 — 이대로 해야 해시가 맞는다

- 대상: `http://localhost:3000` 대시보드 (로그인 상태, 뉴스·채용 로딩 완료 후)
- 측정 속성 20개: display / position / width / height / margin / padding /
  background-image / background-color / color / border / box-shadow / font-size /
  line-height / flex / overflow / transform / opacity / z-index / word-break / white-space
- 범위: `document.body` + 그 안의 모든 요소. `SCRIPT`/`STYLE`/`LINK`는 뺀다
- 뷰포트: 375×684(모바일) / 1280×800(웹) — 812로 재면 잘림이 재현되지 않는다(계획서 §6)
- **로딩 완료 대기**: 요소 수가 3회 연속(1.5초 간격) 같아질 때까지 기다린다.
  뉴스·채용이 비동기로 늘어나 재로드 직후엔 1,179 → 9초 뒤 1,513으로 변한다
- **`closed` / `open` 두 벌**: 닫힌 `<dialog>`의 자식은 computed가 다르게 나오므로
  dialog 13개에 `open` 속성을 붙인 상태로 한 벌 더 뜬다.
  ⚠️ `dialog.close()`를 부르지 않는다 — 속성만 붙였다 뗀다.
  앱의 close 이벤트·저장 경로를 안 태우기 위해서다(핸드오프 27-5: 편집화면 여닫기만으로 전체 저장된다)

### 절차 (한 조합당)

```js
window.__prepTheme('dark')          // 또는 'light'
// → resize_window 로 뷰포트 지정 → 페이지 재로드
eval(localStorage.getItem('__snapjs2'))   // 재로드로 날아간 함수 되살리기
await window.__settle()                    // 로딩 완료까지 대기
window.__cmp2('dark-1280', 'closed')       // 비교
window.__cmp2('dark-1280', 'open')
```

### 양성 대조 / 재현성 (이걸 통과해야 도구를 믿을 수 있다)

- 같은 상태에서 두 번 떠서 차이 **0** — 통과
- **코드를 안 바꾸고 재로드만** 해서 차이 **0/0/0** — 통과
👉 계측 방법을 바꿨으면 이 둘부터 다시 세워라. 방법을 안 세우고 잰 값은 세 번 틀렸다.

## 기준선 해시

요소 수: 다크 1,509 / 라이트 1,501 (테마별 조건부 렌더가 있어 다르다)

| 조합 | closed | open |
|---|---|---|
| dark-1280 | `8bb183801812ae99` | `c635f3781813263d` |
| light-1280 | `92b8276014cff92d` | `cbc712a814cfa40c` |
| light-375 | `628958d814d635ad` | `0def0af814d5452f` |
| dark-375 | `8d8e1ca9180de21a` | `68a2dd181814eaa5` |

요소별 상세는 브라우저 `localStorage`의 `__b2:<조합>:<closed|open>` 8개 키에 있다.
**해시가 안 맞을 때 어느 요소인지 찾는 용도**다. localStorage가 날아가도 위 해시만 있으면
통과/실패 판정은 그대로 할 수 있다(`__cmp2`가 `nowHash`를 같이 돌려준다).

`__snapjs2` 키에는 이 함수들의 압축본이 들어 있어 재로드 뒤 `eval` 한 줄로 되살아난다.
날아갔으면 `snapshot.js`를 콘솔에 붙여넣어라.

## 미검증

- **로그인 사용자 한 명의 대시보드 화면만 떴다.** 비회원 화면, My Page 안쪽,
  모바일 메모 편집 페이지(`.memo-edit-page`)처럼 **상태가 있어야 그려지는 화면은 안 들어 있다.**
  그 화면을 건드리는 단계에서는 그 화면을 따로 열어 전후를 비교해야 한다.
  (다이얼로그 13개의 자식은 `open` 벌에 들어 있다 — 서식툴바·H1~H3 버튼 포함.)
- `open` 벌은 dialog를 **비모달로** 연 것이라 `:modal` / `::backdrop` 규칙이 실제 사용 때와
  다를 수 있다. 전후를 똑같은 방법으로 재는 목적에는 문제없지만 "실제 런타임 값"은 아니다.
- 뉴스·채용 내용이 날짜가 바뀌면 달라진다 → 그때는 `생긴것`/`없어진것`이 0이 아니게 된다.
  **`값이다른것`만 회귀 신호로 읽어라.**
