# 규칙 — 서버 / 파싱 / 프롬프트 / 배치

`src/lib/news/*` · `src/lib/jobs/*` · `src/lib/ai/*` · `src/lib/actions/*` · `supabase/*` 를 만질 때 읽는다.
경위·실측은 `docs/incidents.md`.

## Server Action

- **`"use server"` 파일에는 async 함수 말고 아무것도 export하지 마라.**
  `tsc`도 `npm run check`도 안 잡는다.
- chain은 한 덩어리다 — 앞이 실패하면 뒤도 죽는다.
- UI를 닫는 `setState`를 서버 왕복 뒤에 두지 마라.

## 파싱

- HTML을 **위치(parity)로 파싱하지 마라** — 태그 하나가 어긋나면 뒤 섹션이 전부 죽는다.
  그리고 `<b[^>]*>`는 `<br>`을 잡는다.
- 태그 속성 매칭에서 `[^>]*`는 본문을 새게 하고, 순진한 따옴표 인식은 **페이지를 멈춘다.**
  안전한 형태는 하나뿐이다 — 기존 구현을 재사용해라.
- 화면에 이상한 문자(`?`·`□`·`．`)가 보이면 CSS·폰트보다 **DB 원본을 코드포인트로 먼저 덤프**해라.
  폰트 판정은 폴백을 바꿔 가며 두 번 재라.
- 표기 변이는 양쪽 다 넣어라 — 한쪽만 있으면 없는 것과 같다.

## 프롬프트 / LLM

- 프롬프트의 골드 예시가 오늘 입력과 비슷하면 **그대로 베껴진다.** 예시는 지시가 아니라 정답으로 읽힌다.
- 서버가 채울 필드(`project_id`/`title`/`status`/`selection_mode`)를 모델에 맡기지 마라(환각 방지).
- 검증 실패 시 재시도는 한 번만. 무한 재시도 금지.
- 프롬프트·스키마·모델은 동결돼 있다 → `frozen-features.md`.

## 배치 / guard

- **"오늘 것이 있나" guard는 "그게 누구 것인가"를 같이 물어야 한다.**
  그리고 형제 파이프라인에 같은 guard가 있는지 세라.
- 🔴 **"결과 0건"과 "생성 실패"를 같은 상태로 다루지 마라.** 둘은 결과가 같아도 대응이 정반대다 —
  입력이 없어 0건인 날의 빈 결과는 **정상이고 유효한 캐시**지만(재생성하면 매 요청마다 비싼 작업이
  돈다), 예외로 0건이 된 실행은 **저장하면 안 된다.** 저장하는 순간 그 행이 "오늘 건 있다"가 되어
  그날의 재시도 경로를 전부 막는다(2026-09-27, 뉴스 하루 소실).
  가르는 신호는 결과가 아니라 **예외 시점에 입력이 있었는가**다. 결과의 내용으로 성공을 재판정하는
  처방은 정상 0건을 장애로 오인한다 — 실패한 실행이 애초에 행을 만들지 않게 해라.
- **예외를 `[]`로 삼키면 그 실행은 영원히 "성공"이다.** 삼키더라도 `name: message` 첫 줄은
  실행 기록에 남겨라(stack·요청 본문은 금지 — 자격증명이 섞인다). 그리고 결과가 온전하지 않은 날은
  status를 낮춰라. `success`밖에 없으면 운영 감지가 무력해진다.
- 검사 관문은 "마지막으로 항목을 추가하는 단계" **뒤**에 둬라.
- 중복 제어를 넣었으면 그 **범위**를 적어라 — "한 요청 안에서만"인 것을 "항상"으로 읽는다.
- "점수가 낮으니 안 뽑힌다"는 방어가 아니다 — 창을 열어두면 언젠가 반드시 통과한다.
- 하루 배치 상태는 테이블 두 개에 걸쳐 있다.

## 데이터 모델

- 한 row가 여러 컨텍스트에 동시에 나타나면 그 컨텍스트별 상태를 row의 컬럼 하나로 표현할 수 없다.
- 경계가 데이터에 선언돼 있지 않으면 추측을 정교화하지 말고 **구조를 바꿔라.**
- 목록·개수는 손으로 세지 말 것.
